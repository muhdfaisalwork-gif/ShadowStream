## 1. What this project is

A personal multi-mirror streaming aggregator. It scrapes title metadata + playback links into a
local SQLite catalogue, exports it to Cloudflare R2, and serves it through a Cloudflare Worker API
consumed by an Expo web frontend, an Electron desktop app, and an Android APK.

**No legal/illegal gating** — this is a personal-use app, all sources allowed, player does
multi-mirror auto-fallback. Do not add lawfulness filters back in.

## 4. 🔴 P0 — Electron auto-update is BROKEN. Read this first.

This was reported as "done" in an earlier session. **It is not working.** Two independent faults:

**Fault 1 — the updater points at a dead hostname.**
`packaging/windows/app/package.json` line 51:

```json
"publish": {
  "provider": "generic",
  "url": "https://streamapp-releases.muhd-faisal-work.workers.dev/downloads/"
}
```

That host does not serve the bucket. Verified:

```
streamapp-releases.muhd-faisal-work.workers.dev/downloads/latest.yml   → 404 Not Found
streamapp-catalog.muhd-faisal-work.workers.dev/downloads/latest.yml    → 200, 348 bytes
                                                                       "version: 2.4.0\nfiles:..."
```

`main.js` does call `autoUpdater.checkForUpdatesAndNotify()` on a 5-minute delay
(`resources/app/main.js:112-117`), so the code path is live — it just fetches a URL that 404s, so
the check fails silently (`.catch(e => console.log(...))`). Installed desktop copies will never
self-update.

**Fix (one line, then rebuild + republish the installer):**
```json
"url": "https://streamapp-catalog.muhd-faisal-work.workers.dev/downloads/"
```

**Fault 2 — `ssmoviestvs.site/downloads/*` silently serves the SPA shell.**
The frontend worker has no `/downloads` route, so it falls through to the index.html catch-all and
returns **HTTP 200 with HTML**. Verified: `https://ssmoviestvs.site/downloads/latest.yml` returns
2224 bytes of `<!DOCTYPE html>`. Anything pointing a download link or an updater at that path gets
HTML instead of a file, with no error. Either add a `/downloads/*` route to the frontend worker that
proxies the RELEASES binding, or never link downloads through the site domain.

**Also note:** both `ShadowStream-Setup-x64.exe` and `StreamApp-Setup-x64.exe` exist in the bucket
(78 MB each, near-identical). The worker does a name-substitution fallback between the two prefixes.
Pick one name and make it canonical before shipping, or the two will drift.

## 5. Service worker — hand-edited, do not let a tool regenerate it

`frontend/public/sw.js` is a **custom** file. `app.json` has `web.serviceWorker.input: null`, so
Expo does **not** generate it — `expo-pwa` emits icons/manifest only. Anything that rewrites
`public/sw.js` will silently destroy the logic below.

Current: `VERSION = 'v3'`, 7,666 bytes.

Tiers:
1. **Navigations → network-first.** Deliberate. The shell is content-hashed (`index-<hash>.js`), so
   a cached `index.html` pins a bundle hash that a new deploy already replaced → 404 on its own JS
   → white screen. This happened once already with a `shadowstream-shell-v1` cache that was never
   versioned.
2. **`/_expo/static/*` → cache-first.** Content-hashed, immutable.
3. **Catalogue JSON → stale-while-revalidate, keyed on the full `Request`.**
4. **Stream/resolve/`.m3u8`/`.mp4` → network-only, never cached.** A cached dead mirror is worse
   than a visible error the player can retry.

**The bug that was just fixed — read before touching the cache key.** The catalogue tier used to
key on `url.origin + url.pathname`, stripping the query string. Every
`/api/v1/titles?country=XX`, `?type=movie`, `?genre=…`, `?page=2` call then shared one cache slot, so
whichever response landed first was served for all of them. Symptom: the country page showed
"132,715 titles cataloged from Pakistan" on every country. Fixed by keying on `request` instead.
**Bump `VERSION` on every SW edit** — `activate` only deletes caches whose name doesn't end with the
current `VERSION`, so old caches linger otherwise.

## 9. Environment gotchas that will waste your time if you don't know them

**PowerShell is the default shell here and it is Windows PowerShell 5.1, not pwsh.**
- `&&` is a **parse error**, not a separator. It worked in this session only because each Bash call
  is a fresh shell and single statements don't need it. Use `;` or split across calls.
- Never wrap in `powershell -Command`. Use `powershell -NoProfile -ExecutionPolicy Bypass -File x.ps1`.
- `Select-Object -Name` does not exist (`-Property` does). `tail`/`head` do not exist — use
  `Get-Content -Tail N`.
- Long commands that exceed ~60 s get auto-backgrounded and return a task id. Poll with
  `task_output`. Redirect to a file and run in background rather than piping — several runs died on
  "Parent-death guardian target registration timed out" when output was piped to a long-lived
  pipeline.

**`python` is not on PATH.** Use the absolute path:
`C:\Users\Lucifer\AppData\Local\Python\bin\python.exe`
(`where python` also finds the Microsoft Store stub at `%LOCALAPPDATA%\Microsoft\WindowsApps`, which
exits with "Python was not found". The `bin` one is the real 3.14.)

**Cloudflare blocks the default Python UA with 403 error 1010.** Any live-API probe must send a
browser User-Agent:
`Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/154.0.0.0 Safari/537.36`
This cost a while to spot — it looks exactly like a dead endpoint.

**Unicode print crashes on the cp1252 console.** Probing `/titles?country=TR` returns "Alıkara" and
`print` dies with `'charmap' codec can't encode character '\u0131'`. Print `.encode('ascii',
'replace')` or set `PYTHONIOENCODING=utf-8`.

**Upload ceiling ≈ 64 s on this network.** 78 MB and 106 MB uploads time out and need retries via
`scraper/upload_releases_retry.py`.

**`schtasks /Create /RU SYSTEM /RL HIGHEST` needs an elevated shell** → "Access is denied". The three
catalogue tasks were created as the current user instead, no `/RL` flag. `/TR` must be a single
executable path with no arguments (hence the `.cmd` wrappers); putting args in `/TR` fails with
"Invalid argument/option".

**Deploy flow, both halves:**

```

cd /d "G:\streaming app\frontend"
npx expo export -p web          # → dist/, content-hashed bundle
npx wrangler deploy            # worker "streamapp" → ssmoviestvs.site

```
