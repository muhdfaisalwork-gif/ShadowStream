## 1. Executive Summary & Root Cause Resolutions

### A. Player Playback Failure on *The Last of Us* ("We couldn't find that")
- **Root Cause**: The catalog worker and frontend resolver recently introduced `vidy` (`https://www.vidy.st`), which is the rebranded domain of defunct `videasy.to`. For popular TV shows like *The Last of Us* (TMDB `100088`), `vidy.st` answered HTTP 200 with an error page: *"We couldn't find that — We have searched through our providers and cannot find the media you are looking for!"* (matching the user's screenshot exactly).
- **Resolution**:
  - Permanently banned `vidy` and `vidy_imdb` from `downloads/streamapp-worker/src/index.ts` and `frontend/src/screens/PlayerScreen.js`.
  - Added `'vidy'`, `'vidy_imdb'` to `BLOCKED_SOURCES` and `'vidy.st'`, `'www.vidy.st'` to `BLOCKED_HOSTS`.
  - Enforced proven functional providers in priority order: **VidStuck** (ultra-fast 1080p HTML5), **NontonGo** (multi-server), **VidSrc**, **2Embed**, and **Vidlink**. Live testing confirms *The Last of Us* S1E1 now returns 8 working mirrors with 0 `vidy.st` instances.

### B. Minified React Error #31 on Home Screen (`{season_number, name...}`)
- **Root Cause**: In `MediaCard.js` (line 162), `SurpriseModal.js` (line 171), and `ShadowStreamPlayer.js` (lines 1947, 2866), season and episode properties were rendered directly as JSX children (`S{item.season}E{item.episode}` or `{pick.seasons || pick.seasonCount}`). When items carried a nested season object `{ season_number: 1, name: "Season 1", ... }`, React received the raw object as a child and crashed with Minified React Error #31.
- **Resolution**:
  - Enforced strict scalar coercion (`typeof === 'object' ? obj.season_number : obj`) and template-literal wrapping (`S${sNum}E${eNum}`) across `MediaCard.js`, `SurpriseModal.js`, `ShadowStreamPlayer.js`, and `HistoryScreen.js`.
  - Re-exported and deployed the production web bundle with updated Service Worker (`v56`) to purge stale shells.

### C. Incomplete Streaming Platform Catalogs & Missing Famous Titles (*The Queen's Gambit*, *Arcane*, etc.)
- **Root Cause**:
  1. The search query normalization split strings on apostrophes into single-letter tokens (e.g. `"queen's gambit"` -> `["queen", "s", "gambit"]`). The token `"s"` matched any title containing the letter "s" (*Omar*, *The Messiah*, *Saint Mary*, etc.), awarding them score 250 and burying real results.
  2. The catalog worker only searched static R2 JSON shards. Many platform originals (*The Queen's Gambit* TMDB `87739`, *Arcane*, *Stranger Things*, *Severance*, *The Bear*, etc.) were missing from initial static DB snapshots.
  3. Platform collection shelves (Netflix, Max, Disney+, Apple TV+, Prime Video, Crunchyroll) only browsed static snapshot pages rather than the full, dynamic catalogs of those networks.
- **Resolution**:
  - Filtered search tokens to `tok.length >= 3` for broad token matching and required multi-token queries to match all tokens, eliminating single-letter false matches completely.
  - Implemented live TMDB multi-search fallback in `/api/v1/search` with key rotation across high-quota keys (`42d807f...`, `99a5d84...`, `698d10c...`). Searching `"queens gambit"`, `"arcane"`, or `"stranger things"` now immediately returns the authentic titles with posters, ratings, and playback.
  - Implemented dynamic title detail and seasons fallback in `/api/v1/title/{slug_or_id}`: titles like `the-queens-gambit-87739` automatically fetch complete metadata and all 7 episodes from TMDB live.
  - Implemented live TMDB Discover in `/api/v1/titles?collection=...` mapped to official streaming platform network IDs:
    - **Netflix**: Network `213` (426+ titles live)
    - **HBO Max / Max**: Network `3186` (434+ titles live)
    - **Disney+**: Network `2739` (452+ titles live)
    - **Crunchyroll**: Network `1112` (165+ titles live)
    - **Apple TV+**: Network `2552` (158+ titles live)
    - **Prime Video**: Network `1024`
    - **Hulu**: Network `453`
    - **Paramount+**: Network `4330`
    - **Peacock**: Network `3353`

### D. Direct Root APK Downloads Parity
- **Root Cause**: Direct requests to `https://ssmoviestvs.site/ShadowStream.apk` were previously caught by the SPA `index.html` fallback because the worker only matched `^/downloads/([^/]+)$`.
- **Resolution**: Updated `downloadMatch` regex in `downloads/streamapp-worker/src/index.ts` to `/^(?:\/downloads?\/|\/)([^/]+\.(?:apk|exe|zip|blockmap|yml|json))$/i`, and added `/ShadowStream.apk` and `/ShadowStream-Setup-x64.exe` to `run_worker_first` in `frontend/wrangler.jsonc` and `frontend/worker.js`. Direct requests now serve the 3,026,102 byte APK with `Content-Type: application/vnd.android.package-archive` and `Content-Disposition: attachment; filename="ShadowStream.apk"`.
